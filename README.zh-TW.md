# Looma · 織象

讓想法，逐漸成形。透過人工智慧生成圖片，將想法放進可以自由排列的桌面工作空間。

[English](README.md) · [貢獻指南](CONTRIBUTING.md) · [安全政策](SECURITY.md)

目前是早期原型，介面為繁體中文，僅提供原始碼，尚無可下載的桌面安裝版本。

## 目前原始碼已實作

- 透過原生選檔視窗匯入 PNG、JPEG、WebP，支援一次選取多張。
- 選取、排列與拖曳圖片區塊；平移、縮放、顯示全部圖片。
- 使用本機已登入的 Codex CLI，依文字描述生成圖片。
- 在同一輸入區請求一次性的文字回覆。
- 依提示詞填寫固定圖片拆分模板，檢查並顯示拆分計畫。
- 依計畫逐張生成獨立圖片，顯示預覽並重試失敗區塊。
- 每次成功生成的圖片保留於獨立目錄。

長期方向是讓軟體工程師透過語音與圖片溝通想法。**語音輸入／輸出、工作桌保存、
圖片編輯、圖片歷史與連續對話記憶尚未實作。** SQLite 是已選定但尚未接入的保存方案，
詳見 [資料保存決策](STORAGE.md)。

## 從原始碼啟動

目前開發基準為 macOS、Rust 1.90.0 與 Xcode Command Line Tools。
Linux 與 Windows 尚未驗證。建議使用 rustup 管理工具鏈；專案的
`rust-toolchain.toml` 固定版本並指定格式與靜態檢查元件。若使用 Homebrew 安裝，
需自行確認編譯器與元件版本一致。

在專案目錄執行：

```sh
cargo run --locked
```

匯入、排列圖片不需要登入 Codex。文字與生成圖片功能需另外安裝 Codex CLI，
執行 `codex login`，且啟動 Looma 的環境必須找得到 `codex`。
本次準備文件時，本機 CLI 為 0.162.1；其他版本相容性尚未驗證。
帳號需有對應模型與工具權限，使用限制與費用依帳號及服務規則；Looma 不附憑證或使用額度。

也可以在啟動時載入既有圖片：

```sh
cargo run --locked -- /absolute/path/to/image.png
```

## 圖片拆分規劃

輸入提示詞並按「規劃圖片」，結果面板會顯示畫面尺寸、規劃假設、區塊描述、位置、
圖層、圖片文字與參考區塊。展開「查看完整資料（JSON）」可閱讀完整資料。

固定格式位於 [模板](src/plan_template.json)，每個欄位的用途與規劃要求位於
[填寫規則](src/plan_rules.txt)。每份計畫包含 1～12 個區塊，Looma 會先檢查必要欄位、
型別、版本、識別碼、色碼、畫面邊界，以及只參考先前區塊的規則。
原鎖定檔已有的 Serde 與 serde_json 改為直接依賴，用來解析與序列化資料，授權為 MIT 或 Apache-2.0。

規劃是獨立的文字請求，最多等待兩分鐘，不會生成圖片或修改工作桌；「生成單張圖」仍是獨立操作。
失敗時保留輸入與上一份成功計畫。計畫目前只保留於這次執行期間，關閉程式後不保存。
通過格式檢查不代表拆分符合需求，仍需檢視區塊內容。

### 依計畫生成圖片

確認計畫後按「生成這份計畫」。每個區塊分別發出圖片請求，包含共用視覺規則、
區塊描述、文字、長寬比及透明背景要求。參考區塊會依清單順序以實際圖片附件傳入，
不只在提示詞裡寫名稱。

完成一張就顯示預覽。「已產出」代表圖片能讀取且已保留，不代表文字、去背或拼裝品質已驗收。
程式記錄實際尺寸與透明內容邊界，對超過 5% 的長寬比偏差、透明度不符顯示警示；
文字、去背邊緣與視覺一致性仍需人工檢查。生成階段不改動原圖；拼裝是另一個明確操作。

失敗時保留成功圖片，不相關區塊繼續，依賴失敗圖片的區塊等待參考。
「重試此區塊」重試該失敗項目，再處理被它擋住的區塊，不重做成功圖片。
「停止後續生成」等待目前圖片完成或達到單張五分鐘上限後停止；「生成剩餘區塊」接續未完成項目。
生成期間禁止關閉計畫或重新規劃。進度目前不永久保存；關閉計畫或成功產生新計畫會清除舊預覽紀錄，
但已保留的圖片檔案仍在磁碟上。

### 拼裝已完成的圖片

全部區塊產出後，按「拼裝到工作桌」，同一份計畫只能加入一次。程式會重新讀取所有圖片，
缺檔、損壞或完全透明時整組不加入。場景沿用計畫的尺寸、位置與圖層；相同圖層依原清單順序覆蓋。
顯示時只排除外圍完全透明的留白，內容等比例置中放入規劃範圍，原始檔不變。
不透明留白與比例差異仍可能造成空隙。

整組只有一個標題列，內部仍是獨立圖片。標題列顯示待核對數量，滑鼠停留可看原圖警示。
小視窗可關閉計畫面板，查看完整拼裝結果；關閉或替換計畫不會移除工作桌上的拼裝。
「顯示全部」也包含拼裝群組，一般圖片卡片顯示於群組上方。
點選圖片會以藍框獨立選取，可直接拖曳移動；標題列的圖層選單可選取被蓋住的圖片，
不會改變原本的圖層順序。以 Tab 聚焦圖片後，可用方向鍵每次微調一個場景單位。
點選工作桌空白處取消選取。移動只影響本次工作階段，不改動原始計畫或圖片檔案，超出場景的內容會被裁住。
目前尚未加入整組拖曳、合成匯出、重新開啟後還原；文字與視覺品質仍需人工驗收。

## 資料與限制

- 輸入文字會交給 Codex 及其設定的服務處理，圖片生成需要連線。
  請勿在提示文字或公開回報中放入憑證與機密。
- 選取工作桌圖片不代表它會送給人工智慧。文字回覆與單張生成只送出輸入文字；
  計畫生成只附上該區塊明確參考、先前已生成的圖片。
- 工作桌排列與對話歷史不會保存；匯入圖片仍引用原始檔案，關閉後排列會消失。
- 生成圖片保留於**編譯時原始碼目錄**下的 `generated-images/image-*/generated.png`。
  該目錄必須可寫入；正式散布獨立執行檔前需要調整保存位置。
- 文字最多等待兩分鐘，圖片最多五分鐘。逾時會要求終止直接啟動的 CLI 子程序，
  但不保證所有衍生程序都會被終止。
- 呼叫使用暫時工作階段並略過使用者的主要設定檔，登入沿用本機憑證。
  這不代表外部服務完全不保留資料，也不代表所有其他設定來源都被停用。

## 開發驗證

```sh
cargo fmt -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
```

預設測試不發出真實服務請求；四項略過的測試須另外執行，可能消耗帳號額度：

```sh
cargo test --locked real_reply -- --ignored
cargo test --locked real_plan -- --ignored --nocapture
cargo test --locked real_image -- --ignored --nocapture
cargo test --locked real_batch -- --ignored --nocapture
```

`real_batch` 會真實生成三張點餐元件，其中一張參考先前生成的卡片。

自動測試涵蓋工作桌狀態、幾何運算、拆分計畫、批次順序、附件參數與圖片檢查，不能證明桌面互動正常。
實際操作請依 [人工檢查清單](docs/SMOKE_TEST.md) 記錄結果。

## 英文對照

- **CLI** — 命令列介面，此處是 Looma 在背景呼叫的 Codex 工具。
- **Rust** — 本專案使用的程式語言。
- **SQLite** — 尚未實作的本機內嵌資料庫選擇。
- **rustup** — 安裝與切換 Rust 工具鏈的管理工具。
- **Homebrew** — macOS 套件管理工具。
- **MIT** — 允許使用、修改與散布，要求保留授權及著作權聲明的開源授權。
- **PNG / JPEG / WebP** — 目前可匯入的圖片格式。
- **Xcode Command Line Tools** — macOS 編譯所需的命令列開發工具。
- **JSON** — 供程式解析與檢查拆分計畫的結構化資料格式。
- **Serde / serde_json** — Rust 的資料解析與序列化函式庫，此處用於固定模板。
- **Apache-2.0** — 上述資料函式庫提供的另一種開源授權選項。
