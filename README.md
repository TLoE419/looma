# Looma · 織象

An experimental desktop image workspace for shaping ideas with AI-generated visuals.

[繁體中文](README.zh-TW.md) · [Contributing](CONTRIBUTING.md) · [Security](SECURITY.md)

> Early prototype. The interface is currently in Traditional Chinese. This is a
> source-only project; no packaged desktop release is available yet.

## What works in the current source

- Import PNG, JPEG, and WebP images through a native file picker, including multiple files.
- Arrange image blocks, select and bring them forward, pan, zoom, and fit all images into view.
- Generate an image from text using a locally installed, authenticated Codex CLI.
- Request a one-shot text reply from the same input area.
- Fill a fixed image-block planning template from a prompt and inspect the validated plan.
- Generate a plan's assets sequentially, preview each result, and retry failed assets.
- Keep successful generated images in separate request directories.

The long-term goal is to help software developers communicate ideas through
voice and visuals. Voice input/output, saved workspaces, image editing, image
history, and conversational memory are **not implemented**. SQLite is a planned
storage choice, not a current dependency; see [the storage decision](STORAGE.md).

## Run from source

The current development baseline is macOS with Rust 1.90.0 and Xcode Command Line
Tools. Linux and Windows have not been validated for this project. Use the
standard Rust toolchain manager, rustup; `rust-toolchain.toml` selects the version
and components. A Homebrew Rust installation can also work if it provides the
same compiler, rustfmt, and Clippy.

From the project directory:

```sh
cargo run --locked
```

Image import and arrangement do not require a Codex login. For text replies and
image generation, install Codex CLI separately, run `codex login`, and make sure
`codex` is available in the environment that launches Looma. The local CLI used
for preparation was 0.162.1; compatibility with other versions is not verified.
Your account must support the requested capabilities; model/tool access and
usage charges depend on your account. Looma does not include model credentials
or model access.

Optional: open existing images at launch:

```sh
cargo run --locked -- /absolute/path/to/image.png
```

## Image-block planning

Enter a prompt and press **規劃圖片** (Plan images). The result panel shows the
scene dimensions, assumptions, block descriptions, placement, layering, text,
and reference blocks. Expand **查看完整資料（JSON）** to inspect the complete data.

The contract lives in [the fixed template](src/plan_template.json) and
[the filling rules](src/plan_rules.txt). Plans contain 1–12 blocks. Looma checks
required fields, types, version, IDs, colors, bounds, and backward-only references
before displaying a result. Serde and serde_json, already present in the lockfile,
are direct dependencies for typed parsing and serialization (MIT OR Apache-2.0).

Planning makes one independent text request with a two-minute timeout. It does
not generate images or change the workspace. **生成單張圖** remains a separate
action. Failed requests preserve the input and previous successful plan. Plans
are kept only for the current app session; they are not restored after closing.
Format validation does not establish that the decomposition matches the intent;
review the resulting blocks before using them.

### Generate a plan's images

After reviewing a plan, press **生成這份計畫**. Each block makes a separate image
request using its description, required text, aspect ratio, transparency request,
and shared visual rules. Reference blocks are attached as actual image files in
declared order, using the CLI's `--image` option, not just named in the prompt
([official command reference](https://learn.chatgpt.com/docs/developer-commands?surface=cli)).

The plan panel previews each image as it completes. **已產出** means a retained,
decodable image, not that its text, cutout, or assembly quality has been accepted.
Looma records actual dimensions and alpha bounds and flags aspect-ratio deviations
over 5% and transparency mismatches; text and visual correctness still need review.
Generation leaves source pixels unchanged; assembly is a separate explicit action.

Failed assets leave successful outputs intact; independent assets continue while
dependent ones wait. **重試此區塊** retries that failed asset and then its blocked
descendants. **停止後續生成** waits for the current image to complete or hit its
five-minute timeout before stopping; **生成剩餘區塊** resumes pending work. Successful
assets are never regenerated by these actions. Closing/replanning is disabled
during generation. Progress is session-only; closing a plan or successfully
replacing it discards its preview records, while retained image files remain on disk.

### Assemble completed images

After every block has completed, press **拼裝到工作桌** once to add a scene group.
Looma reopens every file before inserting the complete group. Missing, corrupt,
or fully transparent images reject the operation without adding a partial group.
The scene uses the planned dimensions, positions and layer order; equal layers
retain plan order. Only fully transparent outer margins are excluded for display.
Visible content is proportionally fitted and centered inside each planned frame;
source files remain unchanged. Opaque padding and aspect differences can leave gaps.

The group has one title bar and separate image children. Its warning count remains
visible; hover over the title bar for the source warnings. Close the plan panel to
see the scene unobstructed on smaller windows. Closing/replacing a plan keeps its
assembled group on the desk, and **顯示全部** includes groups. Ordinary image cards
paint above groups. Click a component to select it (blue outline) and drag it directly;
use the title-bar layer selector to select covered components without changing order.
Focus a component with Tab and use arrow keys to nudge it by one scene unit. Clicking
blank workspace clears selection. Movement is session-only and leaves the source plan
and image files unchanged; content outside the scene is clipped. Group dragging,
flattening/export and restoring groups after restart are not implemented.
Text and visual quality need review.

## Data and current limitations

- Prompts are sent to Codex and its configured service. This is not an offline
  image-generation application. Never put credentials or confidential content
  into prompts or public bug reports.
- Selecting a workspace image does **not** attach it to requests. Text replies and
  single-image generation remain text-only; plan generation attaches only the
  earlier generated assets named in that block's reference list.
- Looma does not save workspace layout or conversation history. Imported images
  remain references to their original files. Closing the window loses the layout.
- Generated files are retained under `generated-images/image-*/generated.png` in
  the **build-time source directory**, which must remain writable. This location
  needs to change before distributing standalone binaries.
- Text requests time out after two minutes; image requests after five minutes.
  Timeout handling requests termination of the direct CLI child, but does not
  guarantee cleanup of every descendant process.
- Calls use Codex ephemeral mode and ignore the user's main config file while
  reusing local authentication. This is not a guarantee that the external
  service keeps no data, or that no other local configuration applies.

## Known dependency advisories

The 2026-10-17 full-lockfile RustSec check reports two unsoundness warnings and
three unmaintained-dependency warnings. Strict audit does not pass. The current
macOS dependency graph includes the unmaintained `paste` crate; the other warned
paths concern Linux and Android. No advisories are suppressed. See the
[publication checklist](docs/PUBLICATION_CHECKLIST.md#unresolved-dependency-decisions-before-public-exposure)
for scope and upstream constraints. This prototype is not a security-audited release.

## Development checks

```sh
cargo fmt -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
```

The default tests are local. Four ignored tests make real service requests and
must be run explicitly; they are excluded from CI and may consume account quota:

```sh
cargo test --locked real_reply -- --ignored
cargo test --locked real_plan -- --ignored --nocapture
cargo test --locked real_image -- --ignored --nocapture
cargo test --locked real_batch -- --ignored --nocapture
```

`real_batch` generates three real ordering components, including one reference-dependent card.

Automated tests cover model geometry/state, planning validation, batch scheduling,
attachment arguments, and generated-image inspection/validation, not
end-to-end desktop interaction. See [the manual smoke checklist](docs/SMOKE_TEST.md).
